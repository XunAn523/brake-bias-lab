# Brake Bias Lab · 刹车力矩计算器

用于比较前后卡钳、刹车盘组合的中文桌面工具，支持历史记录、目标盘径反算及 MySQL 数据备份。

版本：1.2.0。Python 3.10+，基础功能使用标准库和 Tkinter；MySQL 备份使用 PyMySQL。提供 Windows 单文件 EXE 打包脚本。

仓库：[XunAn523/brake-bias-lab](https://github.com/XunAn523/brake-bias-lab)。

## 功能

- 对向固定 / 单侧液压活塞浮动卡钳，支持多组活塞直径与数量。
- 三种计算模式：盘径估算、有效半径、完整参数（含摩擦系数与油压）。
- 命名记录列表、搜索、数值排序、CSV 导出和 SQLite 持久化。
- 左侧草稿试算与右侧历史记录查看独立；显式保存后才更新历史结果。
- 每条记录可保存车辆参数，查看不同减速度 g 值下的理想地面制动力分配。
- 固定前盘，按目标前轴硬件力矩占比反算后盘；限制后盘不大于前盘，列出可达范围与候选差值。
- 运行中完整备份数据库，包含全部记录及各自的 g 值车辆参数。
- MySQL 按次保存完整快照，支持连接测试、备份列表和下载恢复文件；后台网络操作，默认 TLS，不持久化密码。

## 运行与构建

源码启动（MySQL 功能需先安装依赖，基础计算可不安装）：

```powershell
python -m pip install -r requirements.txt
python brake_calculator.py
```

Windows 构建（输出到项目目录，自动先运行测试）：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe build_exe.py
```

输出文件为 `刹车力矩计算器_优化版.exe`。打包程序不包含本机数据库；首次运行时在 EXE 同目录创建 `data/brake_history.sqlite3`。

测试：

```powershell
python -m unittest -v
```

42 项自动化测试覆盖已知力矩、单位换算、固定/浮动卡钳、反算方程及不可达目标、载荷转移、数据库备份与失败保护、历史记录持久化、Tk 界面操作，以及 MySQL 快照往返、分块校验、失败回滚和密码不落盘。GUI 测试需要可用的桌面环境和 Tkinter；所有测试记录均写入临时目录。

MySQL 自动化测试使用 SQLite 支持的 DB-API 测试替身验证传输及事务行为，不能替代真实 MySQL 服务器联调。本次未配置真实 MySQL 服务器；连接与服务器权限请在备份窗口中验证。

## 计算口径

每轴两只相同卡钳，左右配置一致；对向卡钳两侧活塞规格对称，数量按单只卡钳两侧合计填写。

有效液压面积 `A`：对向卡钳全部活塞面积除以 2；浮动卡钳为实际液压活塞面积总和。

| 模式 | 单轮力矩或比例因子 | 假设 |
| --- | --- | --- |
| 盘径估算 | `A × D`，仅用于前后比例 | 同油压、同摩擦系数，且有效半径比近似等于盘外径比 |
| 有效半径 | `A × r`，仅用于前后比例 | 同油压、同摩擦系数 |
| 完整参数 | `T = 2 × (P_bar × 0.1) × μ × A_mm² × (r_mm × 0.001)`，单位 N·m | 使用输入的油压、摩擦系数及有效半径 |

`K = T_front / T_rear`，前轴占比为 `K / (1+K)`。盘外径的一半不等于实际有效半径。

g 值分析中，理想前轴地面制动力占比为 `静态前轴配重占比 + g × 重心高度 / 轴距`。若填写不同轮胎滚动半径，硬件地面制动力比为 `K × 后轮胎半径 / 前轮胎半径`。模型假设平路、准静态载荷转移、前后轮胎附着系数相同，不模拟 ABS/EBD 和空气下压力。后轴载荷非正时不输出理想百分比。

## 目标比例反算盘径

先在左侧填写卡钳、前后盘及所需的其他参数。前盘固定 355mm 时，先填写 355，再打开反算窗口并设定后盘上下限。目标是**前轴硬件力矩百分比**，可直接取右侧参考记录的比例；程序不会自动定义“最佳比例”。

盘径估算模式：目标比 `K_target = p/(100-p)`，所需后盘 `D_rear = A_front × D_front / (A_rear × K_target)`。

有效半径 / 完整参数模式：先按相应面积、摩擦系数及油压反算所需后有效半径，再以当前后盘的 `e = D/2-r` 为常数计算新后盘 `D_new = 2 × (r_required + e)`。这是保持刹车片径向几何不变的模型假设；`e` **不是合头安装偏距**。

达不到目标时，显示所需盘径、可达百分比范围和最接近的边界方案。候选尺寸不代表实际产品；卡钳允许盘径、盘厚、扫掠范围、手刹及轮毂空间仍需单独复核。反算只填入左侧草稿，显式保存后才写入记录。

## 数据与备份

数据库位于程序同目录的 `data/brake_history.sqlite3`。升级时保留 `data` 目录即可。

右上角“备份全部记录”通过 SQLite Backup API 生成一致快照，与当前列表筛选无关；先写临时文件，成功后替换目标，失败时保留已有备份。备份包含组合编号、时间、全部参数及每条记录的车辆分析参数。

恢复时先关闭所有计算器窗口，复制保存当前 `data` 目录，再将备份复制到 `data/brake_history.sqlite3`。迁移时可把 EXE 和 `data` 一起复制。CSV 用于查看和交流，不是完整恢复格式。

`.gitignore` 已排除个人数据库、连接配置、密钥、日志、CSV、EXE 和本机构建环境。仓库保存源码、测试、文档及构建脚本；EXE 可另放 GitHub Releases。

## MySQL 数据备份

1. 在服务器预先建立一个数据库，例如：

   ```sql
   CREATE DATABASE brake_bias_lab CHARACTER SET utf8mb4;
   ```

2. 为备份账号配置该库的 `SELECT`、`INSERT` 权限；首次创建备份表还需 `CREATE`、`REFERENCES`。服务器支持 InnoDB 及 utf8mb4 即可，建议使用 MySQL 8.x。
3. 点击主窗口右上角“MySQL 备份”，填写服务器、端口、数据库名、用户名和密码。默认启用 TLS，校验证书及主机名；私有 CA 可选择 PEM 证书。仅对可信的本地连接按需关闭 TLS。
4. 点击“测试连接”，成功后填写备份名称，点击“备份到 MySQL”。密码仅保留在本次窗口内，关闭窗口后清空；“保存连接配置”仅保存非密码设置到 `data/mysql_connection.json`。
5. “刷新备份列表”显示最近 200 次备份。选择一条后，点击“下载所选恢复文件”，下载并校验为 `.sqlite3` 文件。关闭所有程序窗口并保留本地副本后，可按前述方式恢复。

每次备份具有独立编号，允许同名，不覆盖既有快照。存储完整 SQLite 二进制快照，包含全部组合、编号、创建及更新时间、计算参数、结果、每条记录的车辆参数，以及界面无法解析的原始行。使用 SQLite Backup API 生成一致快照，不受搜索筛选影响；未保存的左侧草稿不在备份中。

远端仅使用以下两张表：

| 表 | 内容 |
| --- | --- |
| `bbl_backups` | 编号、名称、UTC 时间、程序/格式版本、字节/分块/记录数量、SHA-256 |
| `bbl_backup_chunks` | 按编号、序号保存的 256 KiB 二进制快照分块 |

单次快照上限 128 MiB。建表完成后，在同一 InnoDB 事务中写入元数据及全部分块；写入失败执行回滚，不保留半条备份。若提交时连接中断而结果未知，请刷新列表核对，程序不自动重试上传。现有表若不是 InnoDB，会拒绝备份。

下载校验格式版本、分块完整性、大小、SHA-256、SQLite 完整性、表结构及记录数量，成功后才原子替换目标恢复文件。下载不能覆盖正在使用的本地数据库。网络请求设有连接/读写超时并在后台执行；任务完成前关闭窗口会被暂缓。本地仍以 SQLite 保存记录，只有点击备份按钮才上传到填写的服务器。

连接与事务接口参考 [PyMySQL 官方文档](https://pymysql.readthedocs.io/en/latest/modules/connections.html)。
